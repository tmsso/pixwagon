A · PlayerChip status (proposal)

PlayerChip · status

Proposal · new props on an existing component

Simultaneous rounds need every chip to say where its player is, without colour. One optional prop, status; everything PlayerChip already does (host, connected, completion) stays, and completion gains a small bar beside its percentage. The swatch always carries hue and hatch.

defaultname, colorIndex Sam activeyourself — border + the word You You hostwaiting room only (exists) Alexhost status="placing"still owes this round Raviplacing status="done"placed or passed this round Samdone status="finished"this picture is complete Jofinished status="away"= connected={false} today Samaway completion0–1 · own board (D9) · exists Sam68%done
Six players at 390 px — reserve two rows
Youdone Samdone Joplacing Ravidone Miaaway Kimplacing

The players row keeps a two-row height for the whole game, so a tag changing from “placing” to “done” never pushes the board down.

Rules
Every status is a word and an outline glyph. The glyphs differ in shape (dots, tick, four squares, broken link), so they read at a glance in greyscale. Dimming means away and nothing else. No coloured dots, no turn ring, no green/red pairs — there are no turns (D1, D2). Screen readers get the status in the chip’s accessible name: “Sam, done”.

Rules
Phone: 5 px cells for three columns, so three pictures fit 358 px. A pack with four or more pictures scrolls the cells sideways inside the component; the who column stays pinned. From 768 px: 8 px cells; from 1180 px: 12 px. Integer steps only, like the board (Annotation 11). Six players on a phone is six rows — the results screen scrolls, the buttons stay pinned at the bottom. The finished picture’s own colours are shown once, at the moment it’s finished (12f, 12i), not here — in a same-board session every row would be the same image. A player who joined mid-game has no board for the earlier pictures: that cell reads “joined later” in place of a board, as the shipped component already does. The shipped version stacks boards under each chip; this one puts pictures in aligned columns so a same-board session compares like with like. Its card in scripts/design-system/cards.tsx is updated and re-synced with the change.

Part B — Phase 6, forward-designed

Annotation 27 · new — A shared link is the front door

Most players meet Pixwagon through /r/CODE, not Home. 02f is the very first screen they see, so it explains the game in one line, shows a real pack picture, and asks only for a name ("No sign-up").

12h then holds the layout of what comes next — the waiting room's code, or the game's frame — so nothing jumps when the snapshot arrives. Under 400 ms only the background is drawn (Annotation 17).

A well-formed code nobody created opens a fresh, empty room rather than failing (LobbyScreen.tsx). So a player alone in a room they reached by typing a code should see one extra line under the player list: "Expected friends here? Check the code with whoever sent it."

Annotation 22 · new — Six seats, two to start, one definition

Supersedes 18. MAX_PLAYERS = 6 lives in @pixwagon/protocol, the one module server and client both import; the web palette is pinned to it by a test. Starting needs two players.

Room codes are four characters with no I, O, 0 or 1 — letters and digits both, so the hint reads "letters or numbers", not pass 02's "A–Z". Mockups use KM4T; pass 02's PIXW can never be issued.

02e keeps the player-facing reason for the cap: six is the most we can tell apart on a board.

Annotation 18 — superseded by 22

Six seats still stands. Superseded on where the number lives (protocol's MAX_PLAYERS, not playerColors.length) and on the code alphabet.

Annotation 26 · new — Can't join, and why the version screen doesn't say "reload"

Three terminal states share one layout: what happened, one line of why, one way forward in thumb reach.

Room full keeps the six-seat reason.

Newer version: an installed PWA keeps serving its cached build on a plain reload (registerType: 'prompt'), so "reload" would loop the player straight back here. The copy sends them to the start, where the update banner (pass 02 frame 10) waits — and 02g2 shows that banner, so they recognise it when they get there.

Open somewhere else (D6): the seat moved to another tab. "Play here" takes it back, and the other tab lands on this screen instead. Never automatic — two tabs taking turns would ping-pong forever.

Annotation 21 · new — Waiting, under simultaneous rounds

There are no turns (D1, D2). Everyone acts at once, and the round closes by itself when every connected player has placed or passed.

So "waiting" means "I'm done, others are still placing" (12a), and every chip says which: a tick and "done", or three dots and "placing" — text plus glyph, never colour or a ring alone. Away players aren't waited on and say "away" instead (24).

The footer names who is left ("Waiting for Jo and Ravi") and says the next round starts by itself, so nobody hunts for a button. No clock, no countdown, anywhere.

Annotation 19 — superseded by 21 and 24

There are no turns (D1/D2): "your turn", "Sam is placing" as a turn and the accent turn ring are gone. The rollback half stands — a fill stays local until the referee accepts it, and nobody else ever sees a rejected one.

Annotation 34 · new — Checking with the room keeps the sheet up

In a room the referee's answer is a round trip, so the wait is visible. Pass 02's 03f rule applies: the sheet stays mounted at 55% with "Placing…" and every control disabled, and the board does not move until the answer lands — then the sheet closes, once.

The live build closes the sheet on commit and dims the offers instead, which drops the board 76 px mid-wait. Status copy stays "Checking with the room…" — accurate, and not alarming.

Annotation 24 · new — Away vs left

Away: the connection dropped. The chip keeps its seat, dims, and reads "away" next to a broken-link glyph. The board is kept, the round doesn't wait for them, and coming back restores everything (D6).

Left: still away when the game ends. Results rank them normally on their real squares, flagged "left" in text — never removed, never zeroed.

Closing the tab makes you away, not gone: with D6 the same link brings you back as yourself, one chip per person.

Annotation 29 · new — No ConnectionPill

Supersedes 20's ConnectionPill half. HudFrame's pill already covers the four states that exist (Connected, Connecting…, Reconnecting…, Offline), warning tone, never red; Home's offline pill shipped separately in Phase 3. A ConnectionPill now would be a component with one caller. Keep the pill inside HudFrame.

Annotation 20 — superseded by 28 and 29

BoardCompare is finalised as a real component (28). ConnectionPill is dropped (29).

Annotation 33 · new · proposal — PlayerChip status

PlayerChip gains one optional prop, status ('placing' | 'done' | 'finished' | 'away'). 'done' is this round; 'finished' is this picture complete. Each status is a word plus an outline glyph of a different shape; dimming is kept for away only.

"You" keeps the accent border and the word You. The existing connected, host and completion props stay (completion's percentage gains a small bar); connected={false} renders the away status.

Six chips with tags wrap to two rows at 390 px. Reserve two rows from the moment a game starts, so the board doesn't shift when a chip's tag changes width mid-round.

Annotation 23 · new — Host powers: helpful, never punitive

The host has four: pick mode and pack (02h), start the game (once — D2), move on after 30 s (12e), and rematch (13c).

Each is phrased as moving the room forward, never as acting on a person: "Move on without Jo", not "Skip" or "Kick".

Guests never see a disabled host button they can never use — they get one plain line saying who decides ("Alex starts the game"). Disabled-not-hidden (Annotation 04) is for controls that will become yours.

Host changes reach guests live, with a short line saying what changed, so nobody is surprised at Start.

Annotation 31 · new — Solo picks its pack on Home, remembered

The Solo button carries the pack it will play ("Garden · 3 pictures") with "Change" beside it. Change opens the picker; picking a pack there returns to Home with it set.

One tap to replay the usual pack, two to switch, and nothing ever stands between Solo and the board. Remembered locally — there is no account to remember it.

Daily shows no choice: it's a fixed rotation. Garden is no longer "coming soon" anywhere (D7).

Annotation 25 · new — Picture cycling and the round budget

A session plays every picture in the pack, in lockstep (D8): the room moves to the next picture only when every picture in play has resolved — complete, or out of rounds. Early finishers wait (12f).

The header shows the stage (three small squares + "2 of 3") and the round within this picture's own budget ("Round 4 of 18"). The wire's round counter keeps running across pictures; the display counts from stageStartRound. A budget is a number, not a clock (D2). In own-board mode a stage's budget is the largest of the pictures in play.

The finished picture is revealed in its own colours once, in a strip above the new board (12i), until your first move on the new picture.

HudFrame already has picture ({ index, count }) and roundBudget (#42). The only change: "Picture 2 of 3" becomes three small squares plus "2 of 3" (the full phrase stays as its accessible name), which frees the width the header needs at 390 px. Solo and daily keep today's header.

Annotation 30 · new — Results: finished pictures first

All-or-nothing (Annotation 15) carries over: a finished picture scores 100, an unfinished one 0.

Rank by pictures finished, then squares filled across the session, then seat. Ties share a rank and both rows say "tied". The headline names the outcome ("Jo wins", "It's a tie"); the ranking is the truth and BoardCompare shows how.

Results read the whole session — [...history, boards]. The Phase 5 screen read only the last picture.

Annotation 32 · new — Rematch is a return, not a restart (D10)

Only the host sees "Rematch". Pressing it sends everyone still connected back to /r/KM4T with the same mode and pack; there the host may change either and presses Start.

Guests see who decides ("Alex can start a rematch") and can leave.

A player who already left the results screen is away: their chip waits in the room, dimmed, and if they open the link again they come back as themselves. Nobody re-enters a code.

Annotation 28 · new — BoardCompare, finalised

Supersedes 20's BoardCompare half. One component for both modes: a row per player (in rank order) and a column per picture. Each cell is that player's board for that picture, drawn in their seat hue and hatch — the same rendering as the game — with "done" or "unfinished" under it in words.

Same board: column headers name the shared picture. Own board: every cell is a different picture, so the name sits under each cell.

Identity lives on the row (swatch + name + rank). Phone: 5 px cells. From 768 px, cells step up with the board rule (Annotation 11).

Revises the component #43 shipped, which stacks each player's boards under their chip: columns line pictures up so a same-board session compares like with like. Its entries already carry what the grid needs.
